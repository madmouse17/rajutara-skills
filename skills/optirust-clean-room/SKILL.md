# optirust-clean-room

optirust mirrors the module split, tool vocabulary, workflows and screen layout of Optitex 15, but it is written **without opening, decompiling, extracting or referencing any Optitex binary, installer, ISO, sample pack, icon, help file or string table**. These rules bind every agent and person, in every task, with no exceptions and no "just to check". Texts: `docs/adr/0001-clean-room-no-reverse-engineering.md`, `docs/adr/0002-dual-license-mit-apache.md`, `docs/adr/0013-astm-rul-is-open-format.md`; also `AGENTS.md`, `CONTRIBUTING.md`, `ATTRIBUTION.md`.

## The three rules

**ADR 0001, no reverse engineering.** The Optitex package that was available was an unlicensed distribution, so even interoperability-motivated analysis was rejected.

- Never open, read, list, mount, extract, hash, screenshot or reference anything from an Optitex install, disc image, installer, sample, icon, help file or string table, wherever it sits on the machine (including folders next to the repo). If a path or archive name contains "optitex", do not touch it, and do not copy that path into code, docs, commits or reports.
- Optitex behaviour comes from **public documentation only** (EFI/Optitex manuals, public help pages, tutorials, reseller training material). Cite the URL (prefer a web.archive.org snapshot with date) in the `## Sources` list of the spec you change, and tag the claim `[src: n]`, as in `docs/spec/03-grading.md`.
- Where public docs are silent, tag the behaviour `[gap]`: do what an Optitex-trained Operator expects (Optitex default where known, industry convention otherwise), and say so (`docs/spec/00-overview.md` §1). Never invent novel UX, and never "recall" undocumented Optitex internals from memory as if sourced.
- Optitex native formats (`.pds`, `.mrk`, `.dsn`, `.ord`, Optitex's own rule tables) are not read or written. Interchange is ASTM D6673 / AAMA-292 DXF with the public RUL file, HPGL/2, PDF and optirust's own open `.optx/.optm/.optc`. Do not add a "best-effort Optitex import".
- Icons, help text, sample patterns, test fixtures and screenshots are **original work** made for this project. `assets/icons/` are original SVGs; `samples/kaos-lengan-pendek/` is generated by `crates/optirust/examples/tshirt_sample.rs` from plain pattern-making arithmetic. The logo is owner-supplied artwork under the project licence (`docs/adr/0014-brand-logo.md`). Never trace, redraw or "match" an Optitex icon or dialog pixel for pixel.
- Names: tool and menu names that Optitex documents publicly are vocabulary and may be used (`GLOSSARY.md`); strings, layouts and wording copied from a non-public source may not.

**ADR 0002, licence and dependencies.** optirust ships as `MIT OR Apache-2.0`.

- No GPL (or AGPL, LGPL-static, "source-available") code, snippets or translations. Seamly2D and Valentina (GPL-3.0) are behaviour and format references only: you may read what they do; you may not copy, port or closely paraphrase their code. FreeSewing (MIT) may be read for behaviour and format reference; copying its code still needs attribution, so write your own.
- Geometry, grading and nesting algorithms are implemented from papers, standards and first principles. Cite the paper in the spec `## Sources` (the nester cites Burke et al. 2006 and ESICUP data, `docs/spec/04-marker.md` §6.3).
- A dependency must be MIT, Apache-2.0, BSD-2/3-Clause, ISC, Zlib, MPL-2.0, Unicode-3.0, BSL-1.0, OFL-1.1 or Ubuntu-font-1.0 (`deny.toml`). `cargo deny check` enforces licences, advisories, bans (`tokio`, `async-std`, `smol`, `wgpu*`) and duplicate versions. One approved exception exists (`target-lexicon`, build-time only; `docs/spec/00-overview.md` §5.9). Do not add `skip`/`exceptions` entries to make a failure disappear.
- New dependency: one-line justification, prefer crates already in `Cargo.lock`, check maintenance and size, never for a few lines of code. Update `ATTRIBUTION.md` and regenerate `THIRD-PARTY.html` with `cargo about generate --locked --workspace --fail -c about.toml packaging/about.hbs -o THIRD-PARTY.html`.
- Contributions are `MIT OR Apache-2.0`; no DCO line, no CLA.

**ADR 0013, RUL is open.** ADR 0001 excludes "Optitex's own rule tables". That does **not** cover the RUL grade-rule file defined with the DXF in ASTM D6673 (and AAMA-292): a public text format that Gerber, Lectra and Optitex all export. optirust reads and writes it (`crates/optirust-io/src/rul.rs`) and `export_dxf` with `GradingExport::RuleFile` writes the sibling `.rul`.

- Fixtures for it are original files written for this project (`crates/optirust-io/tests/fixtures/dxf/graded3.rul`), never a vendor's file.
- Any difference between a real-world RUL and the standard is reported as an `ImportIssue`, never guessed silently.
- This exception does not widen: Optitex's proprietary rule-table files stay out of scope.

## Checklist before you write code

1. What is the source of the behaviour? A public URL, a standard, a paper, or `[gap]` convention. If you cannot name one, stop and ask the owner.
2. Am I about to read a file outside the repo that belongs to Optitex or any commercial CAD product? Do not.
3. Am I copying code, text, an icon or a dataset? Check its licence; if it is not on the allow-list or has none stated, do not commit it (the ESICUP benchmark data has no stated licence, so `scripts/fetch-esicup.sh` downloads it into `target/esicup` and it is never committed).
4. New file format or exchange feature: is it a public standard? If it is a proprietary format, refuse and say ADR 0001.
5. New domain word: add it to `GLOSSARY.md` first; use it as the Rust type or module name.
6. Specs: add `[src: n]` plus the `## Sources` entry, or mark `[gap]`.

## Checklist before you finish

- `cargo deny check` passes with no new `skip`, `exceptions` or `ignore` entries.
- `git diff | grep -ni optitex` shows only prose about Optitex as a product or as public documentation, never a file-system path into an Optitex install.
- New fixtures, icons, samples and screenshots are original; screenshots are taken from the optirust release build, not from another program.
- No ADR was edited: a change of decision means a **new ADR** whose front matter says `status: accepted` and `supersedes: ADR-000N (what changes)` as in `docs/adr/0009-panic-unwind-and-budget-enforcement-split.md`, or `extends: ADR-000N` as in `docs/adr/0013-astm-rul-is-open-format.md`.
- Report what you could not verify; "not verified" is an acceptable answer.

## When a user asks for something that breaks a rule

Examples: "import a `.pds` file", "read the Optitex help CHM for the exact dialog", "port Valentina's grading code", "use this GPL geometry crate", "copy these icons". Decline that route in one sentence, name the ADR, and offer the compliant path: a public standard (ASTM DXF + RUL), a public documentation URL, a permissively licensed crate already in `Cargo.lock`, an original implementation from the paper, or a new superseding ADR proposed to the owner. Do the compliant part of the task.
